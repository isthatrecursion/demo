To deploy and manage containerized applications using Kubernetes on Ubuntu Linux.
Step 1: Open the Ubuntu Terminal
Press Ctrl + Alt + T to open the terminal.

Update the package list:

sudo apt update


Step 2: Install Docker
First, check whether Docker is installed:

docker --version


If Docker is not installed, run:

sudo apt install docker.io -y


Start Docker and enable it to start automatically:

sudo systemctl start docker
sudo systemctl enable docker


Check Docker status:

sudo systemctl status docker


Look for Active: active (running). Press q to exit the status screen.
Step 3: Install kubectl
kubectl is the command-line tool used to communicate with Kubernetes.

Install it:

sudo snap install kubectl --classic


Check the installation:

kubectl version --client


Step 4: Install Minikube
Minikube runs a local Kubernetes cluster on your computer.

Download Minikube:

curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-linux-amd64


Install it:

sudo install minikube-linux-amd64 /usr/local/bin/minikube


Check the version:

minikube version


Step 5: Start the Kubernetes Cluster
Start Minikube using Docker:

minikube start --driver=docker


Check its status:

minikube status


Expected: The host, kubelet, and API server should show Running, and kubeconfig should show Configured.
Step 6: Check the Kubernetes Cluster
Check cluster information:

kubectl cluster-info


Check the nodes:

kubectl get nodes


Expected: The node status should be Ready.
Step 7: Deploy the Nginx Application
Create a Deployment using the Nginx image:

kubectl create deployment nginx --image=nginx


Check the Deployment:

kubectl get deployments


Check the Pods:

kubectl get pods


Expected: The Nginx Deployment should appear, and its Pod should eventually show Running.

Meaning:
- Deployment: Manages the application Pods.
- Pod: The smallest deployable unit in Kubernetes.
- Image: The package used to create the application container.
Step 8: Inspect the Deployment and Pod
First, get the Pod name:

kubectl get pods


Copy the actual Pod name and replace <pod-name> in this command:

kubectl describe pod <pod-name>


Inspect the Deployment:

kubectl describe deployment nginx


These commands display details about the Pod and Deployment.
Step 9: Expose the Nginx Application
Expose Nginx through a NodePort Service:

kubectl expose deployment nginx --type=NodePort --port=80


Check the Service:

kubectl get services


Open the Nginx application:

minikube service nginx


Expected output: A browser opens and displays the Nginx welcome page.
Step 10: Scale the Application
Scaling means increasing or decreasing the number of application replicas.

Check the existing Pods:

kubectl get pods


Increase the replicas to three:

kubectl scale deployment nginx --replicas=3


Check the Pods:

kubectl get pods


Now decrease the replicas to two:

kubectl scale deployment nginx --replicas=2


Check again:

kubectl get pods


Expected: Kubernetes should maintain the requested number of replicas.
Step 11: View Application Logs
Check the Pod names:

kubectl get pods


Copy a Pod name and run:

kubectl logs <pod-name>


This command displays the logs generated by the container in that Pod.
Step 12: Access the Container
Get the Pod name:

kubectl get pods


Enter the container:

kubectl exec -it <pod-name> -- /bin/bash


Inside the container, run:

ls
pwd


Exit the container:

exit


Step 13: Check the Deployment Image
Run the command given in your PDF:

kubectl get deployment nginx -o wide


This displays additional Deployment information, including its container image.
Step 14: Test Kubernetes Self-Healing
Self-healing means Kubernetes can recreate a Pod when a managed Pod is deleted.

Check the Pods:

kubectl get pods


Copy one Pod name and delete it:

kubectl delete pod <pod-name>


Check the Pods again:

kubectl get pods


Expected: The Deployment should create a replacement Pod to maintain the desired replica count.
Step 15: Display All Kubernetes Resources
Run:

kubectl get all


This displays the available Kubernetes resources, such as Pods, Deployments, and Services.
Step 16: Open the Kubernetes Dashboard
Run:

minikube dashboard


This opens the Kubernetes Dashboard, where you can view and manage cluster resources through a graphical interface.
Step 17: Delete the Application
Delete the Nginx Service:

kubectl delete service nginx


Delete the Nginx Deployment:

kubectl delete deployment nginx


Check the remaining resources:

kubectl get all


Step 18: Stop the Kubernetes Cluster
Stop Minikube:

minikube stop


If you want to completely remove the Minikube cluster, your PDF also provides:

minikube delete
